## 2. 本次增量：为什么值得改演示主线

v2 的 T850 案例是 **4 条人工整理的规格**，能证明「追问→收敛」的逻辑，但评委会问一句致命的话：**「这些数据是你们手搓的吧？」**

而这两天核完两本册子后发现：**冠英自己的产品册里就有一张排好的「车型/车桥 → 尺寸」适配表，而且是矢量文字层，不是图片。** 这是企业既有资产，不是我们编的。

所以主案例换成：

```
客户说「我这台天锦KR用什么片」
   ↓
系统从 153 条真实适配表里召回 4 个候选（前A / 前B / 后 / 老款）
   ↓
每个候选带：尺寸、孔数·孔距·片数、册子页码、来源文件
   ↓
追问 1 个问题（前桥还是后桥）
   ↓
收敛到 1~2 个 → 出英文报价草稿 + 待核价单
```

**一句话卖点**：*「你们的知识本来就印在册子里，我们只是把它变成了能查的表。」*

## 5. 功能详细说明

### 5.1 P0-1 适配表管线

**输入**：仅 6 页 —— `kooying catalog.pdf` p27/28/29、`冠隆产品册.pdf` p17/18/19。

**输出**：
- `data/fitment.jsonl`（一行一条，UTF-8，字段见 6.1）
- `data/fitment_quality.md`（质量报告：总条数、可用条数、待核条数、冲突清单、抽检结果）

**必做三件事（按顺序，缺一不可）：**

1. **按版式抽，不按阅读顺序抽。** 先按列 x 带切列，再按 y 就近配对。
   - kooying 列心 x ≈ 137 / 420 / 714 / 1004
   - 冠隆列心 x ≈ 35 / 300 / 630 / 895
2. **丢弃列间数字。** 图注尺寸（`15.91` `39.92` `79.33` `117.7` 这类）落在列与列之间，必须按 x 带排除——第一版就是因为没排它们，把 A/B 两个规格串成了一行。
3. **两册交叉校验。** 同名车型在两册的尺寸必须交集非空；空则标 `status=待核`，进人工队列。

**抽检规则（硬要求）**：人工随机抽 20 条，与 PDF 原文逐字对照，**正确 ≥18 条才算通过**；不通过就只修不扩。

### 5.2 P0-2 车型归一化 + 别名词典

**词条格式**（`data/alias.json`）：

```json
{"东风天锦": ["天锦", "天锦KR", "东风天锦KR", "EQ天锦"],
 "红岩杰狮": ["杰狮", "杰狮C6", "上汽红岩", "GENLYON"],
 "解放虎威": ["虎威", "小虎威", "解放虎V", "J6虎威"]}
```

**归一化顺序**：繁简/异体字（⻛→风、⻰→龙、⻁→虎、⻢→马）→ 去空格与全半角 → 去 `(ABS)` → 去尾部 `前/后/A/B` → 别名映射 → 基础车型名。

**规模**：只做 30~50 条，覆盖演示用例 + 高频车型。**不做自动生成**，这活儿必须人来定。

### 5.3 P0-3 候选匹配服务

规则引擎，**不经过 LLM**：

```
输入: {q, position?, width?, holes?}
1 归一化 → 基础车型名 base
2 召回:
   a 精确: base 命中 → 取该车型全部条目
   b 别名: 命中别名表 → 取目标车型条目
   c 模糊: 编辑距离 Top3（P1，可选）
   d 全失败 → 返回 not_found + 最相近 3 个车型名
3 过滤: position(前/后) / variant(A/B) / width / holes 任一命中则收缩候选
4 置信度:
   高 = 车型精确 + 至少 1 个约束命中 + 候选 ≤2
   中 = 车型精确，但缺前/后或宽度 → 候选 2~4
   低 = 别名/模糊命中，或候选 >4
5 输出:
   candidates[]（尺寸/孔数/孔距/片数/页码/来源册/状态）
   need_ask[]（缺什么就问什么，最多 3 条）
   evidence（页码 + 文件 + 原文行）
```

**防幻觉硬规则（写进代码，不是写进文档）：**

> **候选集只能来自 `fitment.jsonl` 的检索结果。LLM 不参与生成候选。**
> **当 `置信度 != 高` 或 `候选数 > 1` 时，接口返回 `assert_unique=false`，前端禁止显示「就是这一款」。**

### 5.4 P0-4 选型页

现有工作台加一个 tab/路由 `/match`（复用现有模板与样式）。

- 顶部：一个输入框（车型/车桥/旧编码皆可）+ 前/后 下拉 + 宽度、孔数 两个数字框（都可留空）
- 中部：候选卡列表，每卡固定四行
  1. **规格**：`188×155×12.2/14`｜孔数 10｜孔距 120｜片数 8
  2. **证据**：`冠隆产品册.pdf p18 · 第 3 列第 1 行`
  3. **置信度徽章**：高/中/低 + 一句话原因
  4. **待核项**：如「第 3 个数字语义待企业确认」
- 底部：`生成报价草稿`（勾选候选后可用）、`复制追问话术`
- 未命中时：显示「未收录」+ 最相近 3 个车型 + 3 条追问，**不显示任何型号**

### 5.5 P0-6 报价依据卡

勾选候选后生成：

| 区块 | 内容 | 数据来源 |
| --- | --- | --- |
| 规格核对 | 长/宽/厚、孔数、孔距、片数 | fitment.jsonl |
| 依据 | 册子文件名 + 页码 + 原文行 | fitment.jsonl |
| 材质/认证 | 留「待企业确认」占位 | 无 |
| 试验报告 | 报告编号占位（如 `TR-2024-xxxx`，标明 mock） | mock |
| 价格 | **单价与总价留空** | 无价表 |

### 5.6 P0-8 查询日志

每次 `/api/match` 调用落一行 `data/query_log.jsonl`：

```json
{"ts":"...","q":"天锦KR","position":"前","hit":true,"candidates":4,
 "asserted":false,"source":"web"}
```

用途：演示时能说「这 153 条是种子，真实询价日志会把它自动撑大」——把「数据太少」这个质疑当场转成路线图。

## 6. 实现方法

### 6.1 数据管线（负责人 A）

- 工具：`PyMuPDF`（环境已装，`import pymupdf`）
- 关键技巧：`page.get_text("blocks")` 拿 bbox，**用坐标做配对，不用顺序做配对**
- 字段定义（`fitment.jsonl` 一行）：

```json
{"id":"GL-p18-c1-r1","brand":"GUANLONG","src":"冠隆产品册.pdf","page":18,"cell":"c1r1",
 "vehicle_raw":"东风天锦KR前A","vehicle_norm":"东风天锦KR","position":"前","variant":"A",
 "size_raw":"188×155×12.2/14","l":188,"w":155,"t1":12.2,"t2":14,
 "holes":10,"pitch":120,"pieces":8,"oe":[],
 "status":"ok","confidence":0.95}
```

- **`holes/pitch/pieces` 三个字段的语义尚未经企业确认**（我按「孔数/孔距/片数」理解）。落库时保留 `raw_nums:"10 120 8"` 原串，语义确认后回填，不阻塞开发。

### 6.2 匹配服务（负责人 B）

- Flask blueprint：`/api/match`（POST）、`/match`（页面）
