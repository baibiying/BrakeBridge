# BrakeBridge AI 产品需求文档

- **产品名称**　冠英展会买家筛选与询盘助手
- **业务场景**　冠英商用车制动件出海与展会邀约
- **项目归属**　INTERCITY HACK 湖州站 · AI + GTM
- **文档版本**　v1.0 · 团队评审稿 · 2026-11-21
**适用读者**　冠英外贸业务负责人、参赛团队、产品验收人员

## 1. 产品概述

冠英外贸销售每天需要从海关记录、现有客户名单和社媒留言中判断谁值得联系，准备展会邀约，并在买家提出询价后及时接手。BrakeBridge 把这项工作放进两个页面：**买家名单**和 **Facebook 询盘**。

销售导入一批买家资料后，可以查看哪些企业经营商用车制动件、有哪些采购证据、是否出现来华或到展意向，并起草英文邀请。销售也可以录入自有 Facebook 产品帖的评论，查看采购意向、产品需求和信息缺口，生成英文回复、分配负责人并记录下一次跟进。

**首版交付标准**是让销售在一台电脑上独立完成「找证据 → 选买家 → 写邀约」和「接评论 → 判意向 → 写回复 → 分派 → 导出」两条流程。Facebook 是首版唯一的社媒渠道。型号核对从 T850 和新 T850 的少量真实目录条目开始。

## 2. 企业背景与真实需求

冠英主要面向商用车售后市场和外贸业务，相关品类包括鼓式刹车片或衬片（brake lining）、盘式刹车片（brake pad）和制动蹄（brake shoe）。外贸团队已有海关数据、孚盟 CRM、展会名片、社媒渠道和产品目录。赵总在开幕式讲题和问答中指出了以下问题。

## 3. 用户与主要使用场景

| 用户 | 要完成的工作 | 需要看到的结果 |
| --- | --- | --- |
| 外贸销售 | 选择重点买家、编辑邀约、处理评论、继续跟进 | 企业与品类、判断依据、回复草稿、待确认信息、下次跟进日期 |
| 外贸负责人 | 检查名单质量、纠正判断、分派询盘 | 分级依据、负责人与状态、改判原因、可导出的跟进清单 |
| 产品或技术同事 | 核对目录规格，补充材质、适配和内部价格依据 | 客户原话、来源页、候选、缺项、待核价单 |
| 赛事团队与企业试用人员 | 看完整流程，验证真实数据和实际效果 | 可追溯的来源、可复演的操作结果、明确的验证范围 |

这些是业务职责。当前演示环境为单实例工作台，页面中的「负责人」是销售分工字段。企业部署需要按实际人员组织和数据范围确定账号与权限。

### 场景 A · 展会前筛名单

1. 销售取得授权的海关或 CRM 导出，整理成 Excel 或 CSV 后上传。
2. 工作台聚合重复企业与证据，按优先级提供待联系名单。
3. 销售打开买家卡，一次核对经营品类、采购能力、中国采购、来华和到展依据。
4. 销售确认是否值得跟，生成并编辑英文邀约，保存负责人及下次跟进日期。
5. 有明确行程时确认时间。行程未知时通过邀约询问是否到展。

### 场景 B · 产品帖收到询价

1. 自有产品帖收到评论。销售通过粘贴、授权 CSV 或已配置的 Facebook 同步录入评论。
2. 系统保存原文和来源，再做意向识别。明确询价进入待回复，普通互动留档。
3. 销售打开评论，核对产品、编号、数量、单位及现有规格。企业身份或直接采购能力证据不足时显示待核。
4. 销售编辑英文回复，补问必要信息，关联买家并保存跟进。
5. 客户补充同一会话的规格后，销售查看目录候选和页码，导出待核价单。

### 场景 C · 一个客户谈不下来

从已知客户找到同市场、同制动品类的候选，从中优先查看已有采购依据的企业。销售查看每家的匹配来源，挑选一家公司继续联系。后续获取可核验的供应链、品牌代理或股权资料时，再补充真实关系。

优先级用于分配比赛开发和验收时间。**P0** 为必须能演示的工作流，**P1** 为本版可验证的增强能力，**P2** 为企业试点和产品后续。

| 优先级 | 需求 | 当前状态 |
| --- | --- | --- |
| P0 | Excel / CSV 买家导入、去重、筛选、证据核验 | 已实现，本地样例可复演 |
| P0 | Facebook 评论粘贴和授权 CSV 导入 | 已实现，本地中文样例可复演 |
| P0 | 询盘意向、英文邀约与回复、销售跟进及 CSV 导出 | 本地规则流程已验证，赛事账号上的模型调用待实测 |
| P1 | Facebook 指定产品帖官方同步、Webhooks 实时通知 | 实现了适配器和签名验证，完成了模拟事件回归，待团队 Page 真机验证 |
| P1 | T850 / 新 T850 目录查询、缺项追问和待核价单 | 已录入并核对四条目录规格，本地验证覆盖了不同宽度 |
| P1 | 同市场、同品类的相似买家 | 已有库内匹配逻辑，销售认可结果待试点验证 |

首版的交付重点是**名单、Facebook 评论、销售跟进**。全网采购商监测、跨平台私信收件、自动群发、全车型适配、正式成交报价和 CRM 双向同步属于后续评估范围。若正式赛题将型号查询列为必交，团队优先验收已核过的 T850 小案例。

## 5. 功能需求

### F01 · 名单与证据导入 · P0

**作用**　把分散记录转成销售能核对、能再使用的买家名单。

- 支持固定模板 CSV 和 XLSX，Excel 读取第一张工作表。必填公司名和来源原文。每条证据可包含国家或地区、企业域名、来源类型、链接或记录编号、记录日期和数据类型。
- 导入结果展示新增企业数、新增证据数、重复数和跳过原因。空文件、重复表头、缺必填字段和格式不符时显示可理解的提示。单次上传上限为 5 MB，表格最多 1,000 行。
- 同一买家可有多条证据。公司聚合以域名或规范化公司名与国家为主要线索。出现公司简称、母子公司、同名企业等疑似冲突时，由销售核对。
- 同一来源、同一原文和相同记录重复导入时只保留一条证据。不同日期或不同原文保留各自来源。
- **验收**　导入六行中文名单，生成四家买家与五条独立证据，第二次上传同一文件新增为零。来源可从买家详情复查。

### F02 · 买家分级与采购证据 · P0

**作用**　告诉销售今天先联系谁，以及还差哪项证据才值得进一步投入。

| 核验项 | 可用依据 | 销售据此判断 |
| --- | --- | --- |
| 商用车制动品类 | 货描、企业官网、目录明确对应卡车或商用车的制动产品 | 产品是否对口 |
| 采购或进口能力 | 授权采购记录中的买方或收货人角色，或企业已核实的采购信息 | 企业是否具备值得跟进的采购角色 |
| 中国采购记录 | 原产地或发货来源、采购记录中的中国交易依据 | 是否符合本次展会邀约优先条件 |
| 来华计划 | 有日期或行程线索的买家自述、销售确认或获准使用的记录 | 是否值得尽快沟通见面 |
| 到展意向 | 买家报名、自述、明确回复或确认约见 | 草稿应询问计划还是提出约见 |

- 系统分级为**优先联系、待核实、暂缓**。产品匹配与采购能力都有可核依据时进入优先联系。只有一个条件成立、信息待补或证据冲突时待核实。存在明确品类不符证据时暂缓。
- 结论显示「有依据」「客户自述」「待核」「明确不符」或「证据待复核」。同一原文可以支持多个判断，界面集中展示并允许按依据编号跳转。
- 买家可按公司名、国家、域名、优先级和来源筛选。人工可改判并填写原因。修改判断后继续保留来源原文。
- **验收**　从中国进口重卡鼓式刹车片的中文样例进入优先联系。只证明经营相关产品的样例为待核实。仅经营乘用车滤清器的样例为暂缓。仅有采购泛汽配记录的企业不直接进入优先联系。

### F03 · Facebook 评论收件与会话 · P0 / P1

**作用**　把自有产品帖的采购留言变成可操作记录，减少漏回。

- **P0** 支持销售粘贴原文和导入授权评论 CSV。必填评论正文。补充字段包括来源链接、公司、评论 ID、帖子 ID、Page ID、收到时间和会话 ID。
- 入库时保存原文与渠道来源，并标明人工录入、CSV 导入、官方同步或 Webhook。对有平台 ID 的记录，以渠道、Page 和评论 ID 去重。相同会话可继续追加客户回复并核对字段变化。
- **P1** 支持团队或企业授权管理的一个 Page 和指定产品帖。先用 Graph API 手动同步验证评论读回。具备 HTTPS 回调和相应应用权限后，订阅 `feed` 新评论事件。
- 官方读取失败、权限不足或令牌过期时保留已导入记录，并提示销售使用粘贴或 CSV。收到无关帖子、重复事件或无效签名时保持收件箱数据一致。实际评论由团队测试 Page 或冠英授权 Page 提供。
- **验收**　本地演示可粘贴一条中文评论并看到原文。对于官方接入，使用另一位队员在测试帖留下带唯一数量的真实评论，核对原文、评论 ID 和来源，重复同步无新增。

### F04 · 意向分析与询盘画像 · P0

**作用**　告诉销售这条消息是否值得现在回复，以及该问什么。

| 情况 | 默认判断 | 默认进入 |
| --- | --- | --- |
| 明确询价、询问起订量且给出产品或编号、明确提议约见 | 高意向 | 待回复 |
| 索要目录、询问规格、问展位或展会信息 | 中意向 | 待复核 |
| 点赞、祝贺等普通互动 | 普通互动 | 留档 |
| 只有泛泛的价格问题、字段冲突或信息太少 | 待确认 | 待复核 |

- 提取意图、语言、产品、编号、数量和单位。原文明确时补充前后位置、尺寸、孔数、材质、车桥和目的地。显示依据原句及仍待补充的字段。
- 销售可关联已核实的买家，也可先保留未关联询盘。不同渠道、不同账号或相同显示名称需要业务确认后关联。
- AI 使用保存的原文和采购证据。结论要能回查原句，数值与单位需要校验。批量导入先提供规则结果，详情可按需用模型核查。模型异常时可继续查看原文、采用规则结果或人工改判。
- 询盘意向和买家采购资格各自展示。明确询价可优先回复，企业身份和进口能力继续接受核实。
- **验收**　「想订 200 套 T850 前刹的鼓式刹车片」进入待回复并提取 200 套。索取展位号进待复核，普通点赞进留档。模型返回无依据内容时，评论已经入库且仍可人工处理。

### F05 · 展会邀约与询盘回复 · P0

**作用**　生成销售可以核对、编辑并复制发送的下一条消息。

- 买家详情生成英文展会邀约。优先引用已核验的目标品类。已确认到展时提出约见，计划未知时询问参展安排。展会名称、日期、场馆和展位号取企业确认后的配置。
- 询盘详情根据产品、数量、编号、规格和意向生成英文回复。信息不足时提出具体追问。T850 可优先询问原件宽度、车桥或编号。
- 草稿支持编辑、保存和复制。发送、约见及对外承诺由销售确认并执行。系统以草稿和跟进状态记录这次处理。
- **验收**　展位未配置时草稿省略展位。询价只有产品无数量时追问数量。同一 T850 前刹有多个候选时，草稿包含能区分候选的问题。

### F06 · 管理工作台、分派与导出 · P0

**作用**　让销售找到今天要处理的记录，并让同事能接着跟。

- 界面采用中文后台。左侧导航进入买家名单和 Facebook 询盘，列表支持搜索和状态筛选。记录详情按采购证据或留言规格、邀约或回复跟进分区。
- 买家状态包括待联系、已联系、等待回复、已跟进。询盘状态包括待回复、待复核、留档、已跟进。负责人可以认领、变更状态、填写下次跟进日期及人工改判理由。
- 买家详情可以打开关联的 Facebook 询盘。表格导出全量买家和互动记录，内容包含来源、状态、负责人、下次跟进、判断理由及已保存的草稿。
- **验收**　处理一条询盘后能在买家详情找到关联，刷新或重启服务后保留记录，CSV 中的负责人、状态和草稿与页面一致。

### F07 · T850 目录候选与待核价 · P1

**作用**　用真实目录帮助销售确定差哪一项信息，减少选型过程中来回确认。

- 目录先使用 T850 与新 T850 的四条规格，按产品系列、前后位置、宽度与孔数缩小范围。每个候选展示目录名称、尺寸和来源。来源为《冠隆产品册》PDF 第 12 页、印刷页第 22 页。
- 客户只说 T850 前刹和 10 孔时，保留 T850 前刹与新 T850 前刹两项。客户确认 140 mm 时选出 T850 前刹目录行，150 mm 时选出新 T850 前刹目录行。
- 车型单一但车桥更换、字段矛盾或尺寸无法命中时，要求补查车桥、原件编号或实物。候选结果用于询盘核对，交由销售或技术人员确认实际适配。
- 待核价单包含评论原文、候选、目录页、已有尺寸、数量、材质、目的地、缺项和负责人。首版的单价和总价保留空值，由企业核价后填写。
- **验收**　核对二选一、140 mm、150 mm、145 mm 无匹配及冲突五种情况。导出的单价和总价为空，候选页码与页面一致。

### F08 · 相似买家和关系查证 · P1 / P2

**作用**　从已有买家继续找到值得联系的替代对象。

- 首版优先在已导入的候选中寻找同市场、同商用车制动品类的企业，最多展示三家，显示产品来源，采购能力有证据时优先排序。
- 后续根据企业提供的行业数据建立已验证关系，区分同类企业、竞争对手、关联公司、上下游和未知关系。每条关系显示证据、来源日期和审核结论。
- **验收**　用一个已知客户作为起点，团队能说明推荐企业相似在哪一条业务线上，销售能打开出处并判断是否联系。

## 6. 数据、接口与运行要求

| 对象 | 最少字段 | 关键规则 |
| --- | --- | --- |
| 买家 | 企业 ID、企业名称、国家、域名、资料类型、优先级、负责人、状态 | 从证据生成初判，人工改判需要理由。 |
| 证据 | 所属买家、来源类别、链接或编号、日期、原文、数据类型 | 来源可查，同一原文可被多个核验项引用。 |
| 互动 | 渠道、Page、评论 ID、帖子 ID、会话 ID、收到时间、原文、录入方式 | 评论先入库，再做识别，支持按 ID 去重。 |
| 询盘分析 | 意图、优先级、证据片段、产品与规格、缺项、生成方式 | 保留规则或模型来源，跟进人员可人工复核。 |
| 销售跟进 | 关联买家或询盘、负责人、状态、下次跟进日期、草稿、改判原因 | 重启后可查，可导出交接。 |
| 目录条目 | 系列、前后位置、尺寸、孔数、目录文件、PDF 页码和印刷页码 | 样本内部 ID 与企业货号分别记录。 |

**数据来源规则**

- **企业授权数据**用于实际业务试点。优先获得 5–10 条脱敏买家记录及正反例，保留必要的货描、买方角色和销售判断。
- **公开资料**用于企业暂时未交付样本的试用分支。先从一个市场整理可核验候选，当前有 5 家美国企业的公开资料。官网原文和链接可追溯，结论限于来源支持的字段。
- **演示数据**用于中文演示和回归。当前包含四家中文买家、五条独立证据、五条中文评论。数据明确标记，买家名称和交易场景按合成样例处理。
- 销售可将合适的脱敏样本装入本地演示库。生产数据、令牌、比赛密钥及 SQLite 工作库由团队在仓库之外管理。提交 Gitee 的资料使用合成、公开或获准展示的内容。

**实现与运行约束**

- 服务采用 Python 3.12、Flask / Jinja、Flask-WTF、SQLite 和 Waitress。前端采用本地 Tabler Core 和 Tabler Icons。CSV 与 Excel 按固定模板进入同一套规则。详见[团队协作与开发环境](../README.md)。
- 本地演示默认使用独立数据库。两页支持桌面和窄屏操作，后台表单做 CSRF 校验。Facebook 回调以单独路径验证 Meta 签名，按配置的 Page 和帖子接收事件。
- 模型参数与授权配置由服务端读取。模型调用超时、签名失败、重复导入或进程重启时，应能在对应页面继续查看已保存数据。
- 功能入口为买家名单、Facebook 询盘、CSV 导出、待核价单及另行配置的回调。企业试点若需多人独立账号、角色访问控制或 CRM 回写，先明确数据权限和部署方案。

## 7. 验收标准、试用指标和演示

| 用例 | 操作 | 通过标准 |
| --- | --- | --- |
| U01 名单去重 | 从空库导入中文名单两次 | 首次 4 家、5 条证据，第二次新增为零。 |
| U02 证据分级 | 查看海湾重卡、圣保罗商用车和安第斯乘用车 | 分别为优先联系、待核实和暂缓。查看详情能追到原文。 |
| U03 无企业样本 | 导入公开企业候选并判断是否值得跟进 | 可显示公开品类证据。中国采购、进口能力、来华和到展字段按实际资料保留待核。 |
| U04 询盘承接 | 导入中文 200 套询价、展位咨询和点赞 | 分别进入待回复、待复核和留档，原文与来源可查看。 |
| U05 模型回退 | 模拟超时、响应异常或引用不存在 | 评论仍可读取，规则或待复核状态可追溯，人工操作可继续。 |
| U06 跟进保存 | 生成草稿、编辑、关联买家、认领后重启 | 页面及导出中保留编辑内容、负责人和状态。 |
| U07 选型核对 | 测两条候选、140 mm、150 mm、145 mm 和冲突字段 | 候选变化符合目录，缺项能触发追问，待核价单可导出。 |
| U08 官方渠道接通 | 团队成员在指定 Page 产品帖发一条独特询价，触发同步或回调 | 工作台出现实际留言、评论 ID 和来源，同一评论重复到达只保留一条。 |
| U09 操作可用性 | 由未参与开发的队员在桌面和窄屏操作 | 能独立完成导入、筛选、编辑、认领及导出。 |

**试用时记录什么**

| 指标 | 统计方法 |
| --- | --- |
| 买家前五认可率 | 销售认可的企业数 ÷ 实际评审的前列企业数。保留被否决的理由。 |
| 询盘漏收与误入池 | 对照业务人员标注，记录有效询盘总数、未入池数和误入待回复的普通评论数。 |
| 完成一次跟进所需时间 | 记录从选中买家或打开询盘到保存可用草稿及负责人所需时间。与原流程比较需使用相近难度记录。 |
| 询盘可交接率 | 已进入待回复的业务询盘中，具有负责人及明确下一步的记录比例。 |
| 展会有效会面 | 分别统计确认邀约、客户回复、约定见面和实际会面。结果使用实际展会记录。 |

功能样例用来复演，企业效果使用真实授权记录验证。小样本结果展示分子、分母和误判案例。官方模拟事件计入工程测试，真人消息另有验收记录。

**建议演示顺序**　先导入中文名单并打开海湾重卡配件，看同一采购记录如何支撑品类、采购角色和中国来源。生成邀约后切到 Facebook，打开 200 套询价，显示如何补问宽度、确认 140 mm、保存负责人并导出待核价单。有真实 Page 授权时，再展示一条现场留言进入收件箱。
