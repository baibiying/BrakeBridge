## 1. 目标与使用场景

冠英外贸销售在展前需要判断哪些海外企业值得联系，收到产品帖留言后需要判断哪些人值得立即跟进。比赛交付从精准获客到销售跟进的完整流程，覆盖两条入口。

1. **展前拓客**。导入历史海关、CRM 或公开企业资料，查看筛选依据，生成结合买家品类的英文展会邀约，记录负责人和下次跟进时间。
2. **承接询盘**。从团队或企业自有 Facebook 产品帖收集评论，识别采购意向，提取已知信息与缺口，生成英文回复草稿，由销售审核、复制并跟进。销售可以直接从一条新评论开始。

## 2. 功能与优先级

### P0 · 比赛必交

| 功能 | 用户操作与验收标准 |
| --- | --- |
| 买家名单导入 | 上传固定模板 Excel 或 CSV。保留证据原文、日期、来源和数据类型。回显新增、重复、跳过数量及原因。优先用冠英授权的脱敏样本。暂缺授权记录时，选一个目标市场，用 5–10 家真实企业的公开资料构建候选名单。 |
| Facebook 自有帖评论入口 | 粘贴一条留言或导入获准使用的评论 CSV。每条记录保留原文、时间、来源链接及可用的帖子和评论 ID。评论先存为互动，再根据意向决定是否跟进。 |
| 买家证据卡 | 分别展示品类匹配、采购能力、中国采购和展会意向。结论附支持判断的原文与出处，缺少信息标为「待核」。销售可以调整优先级并填写原因。 |
| 评论意向卡 | 展示语言、产品或编号、数量与单位、采购信号及缺失信息。意向分为高、中、低、待确认。公司等自报身份标为「客户自述」，有依据后再关联库内企业。 |
| 跟进与导出 | 明确询价、约见进入「待回复」，索目录等中意向和无法判断的留言进入「待复核」，普通互动「留档」。销售可人工转入线索池、改判并留原因、指派负责人、设下次跟进时间、标记已跟进并导出 CSV。 |
| 英文邀约与回复 | 对历史名单按品类生成邀约，参展计划未知时先问行程。对评论优先补问公司、数量或关键规格。展位号取自已确认的展会配置，缺失时省略。草稿支持编辑、保存和复制，由销售发送。 |

### P1 · 按条件验收

| 功能 | 开工条件与实测标准 |
| --- | --- |
| Facebook 官方评论同步 | 优先验证。有团队可管理的 Page 和指定产品帖时，用 Graph API 实现「同步评论」。队员在产品帖留言后，从工作台读回对应原文，并进入与粘贴、导入相同的分析流程。同步通过且具备权限后，再接 `feed` Webhook。记录是否收到真人事件。 [Meta 评论接口](https://developers.facebook.com/docs/graph-api/reference/post/comments/) · [Meta Page Webhooks](https://developers.facebook.com/docs/graph-api/webhooks/getting-started/webhooks-for-pages/) |
| WhatsApp 测试收件 | 有可用测试业务号码和 HTTPS 回调时，由队员用手机回复，核实入站消息是否进入同一工作台。 [WhatsApp 官方快速入门](https://developers.facebook.com/documentation/business-messaging/whatsapp/get-started/) |
| T850 候选与待核价单 | 主流程通过后，使用四条 T850 系列目录规格。前刹、10 孔保留两个候选，补 140 mm 可定位 T850 前刹，补 150 mm 可定位新 T850 前刹。输出候选、页码、数量和待核事项，缺企业价格时单价与总价留空。若 B1X 正式细则要求型号查询，A 确认后将这个案例升为 P0，实时接入顺延。 |

## 3. 判定与数据规则

- **分别判断买家和消息。** 买家分级回答谁值得邀约，评论优先级回答哪条消息先回。明确询价或问起订量的评论可先回，同时保留公司身份及进口能力待核。
- **每个结论用对应证据。** 企业产品页支持品类判断。进口角色或交易记录支持采购能力，中国来源的采购记录支持中国采购，客户回复或授权的报名信息支持展会意向。模型抽取的产品编号先保留原话，经目录核对后再展示具体候选。
- **先保存原文，再分析。** Flask/Jinja 提供买家工作台与互动收件箱，SQLite 保存原文、来源、分析与跟进状态。B 封装比赛专户模型调用，C 复用。对模型输出校验字段与原文引句。超时或无效时保留原记录、提供可编辑的规则草稿，并标识待复核与生成方式。
- **重复导入保持一条待办。** 买家按已核实的企业标识聚合，证据按来源去重。互动用渠道、账号、外部消息 ID 去重。官方同步和 CSV 导入保留相同账号和评论 ID，以便归到同一条互动。缺少可靠身份线索时由销售确认关联。
- **标出数据和接入来源。** 区分企业授权、公开资料、合成样例，以及真人渠道事件、后台测试和手工导入。只展示获准使用的数据。

## 4. 验收用例

| 场景 | 操作与预期 |
| --- | --- |
| 名单重复导入 | 上传 6 行买家联调样例，得到 4 家企业、5 条证据。原样重传后，新增为 0。 |
| 证据不足与展会邀约 | 用只有官网产品证据的买家测试，品类可判、采购能力待核。参展意向未知时先问行程，展位未录入时草稿省略展位。 |
| 评论分类与跟进 | 粘贴合成留言 `Please quote 217 sets of T850 front brake linings.` 和 `Congratulations on the new video!`。前者保留 `217 sets`、原文和依据，进入待回复。后者进入留档。索目录的评论进入待复核，支持人工转入待回复并留原因。 |
| 认领、重启与导出 | 指派负责人、设置下次跟进、编辑并保存英文草稿。重启后核对原文、判断、负责人和草稿，检查导出 CSV 与工作台记录一致。 |
| 模型超时 | 用新记录触发超时。原文仍可查看，状态可复核，规则草稿可编辑。 |
| 官方同步（如具备权限） | 队员在指定产品帖发一条可辨认的测试评论并同步。以工作台读回对应原文为通过。用相同账号与评论 ID 重复导入后，待办维持一条。 |
| T850 追问（如纳入演示） | 先输入前刹、10 孔，显示两个候选并追问宽度。分别补 140 或 150 mm，核对命中的不同目录行。缺价格时生成待核价单，缺值留空。 |

路演演两笔业务。先从真实企业资料筛一位买家，展示一条证据和英文邀约。再处理一条真人同步或手工导入的评论，展示采购信号、缺失信息、回复草稿和后续动作。T850 实测通过时，可在第二段加一次宽度追问。

A 用未参与开发调试的买家与留言做盲测，记录销售认可数与实际评估数、漏收询盘数和误收留言数。无企业反馈时，指标标明为团队内部测试。

## 5. 后续方向

| 方向 | 业务价值与启动条件 |
| --- | --- |
| 多渠道实时收件 | 用一个待回复队列承接 Facebook 评论、Messenger 和 WhatsApp。需要企业账号授权、平台权限和原收件箱对账数据。 |
| 相似买家与持续拓客 | 从已知买家找同市场、同品类、同采购角色的候选。先收集可核验的贸易或企业资料，请销售评估一国一品类的推荐结果。 |
| 全目录、跨码与实物选型 | 用旧件编号、尺寸和车桥信息缩小候选范围。需要企业技术人员核验目录、跨码和样件。 |
| 正式核价与孚盟 CRM 对接 | 将确认的规格推进到企业可发出的报价，减少重复录入。需要有效价表、审批规则、CRM 测试权限和字段样本。 |
