## 2. 决策日志（已拍板）

| # | 决策 | 结论 | 代价 |
| --- | --- | --- | --- |
| D-01 | 分工方式 | **按三个功能板块切**，每人从页面到数据全包 | 三个人技术面都要摊开，深度换广度 |
| D-02 | 是否按前后端切 | 不按 | 无 |
| D-03 | 技术框架 | Flask 3 + Jinja2 + JSON 文件，不用数据库 | 查询性能一般，但 153 条够用 |
| D-04 | 合并保证 | 每人独占一个 `features/<功能>/` 目录 + 三份冻结文件 | 共享改动必须找 PM |
| D-05 | 跨功能调用 | 只有一个 URL：`/fitment?q=&from=` | 拓客到询盘是 P1 |
| D-06 | 速配数据起点 | 用已有 CSV，不重抽 PDF | 若 CSV 错率高需回退，风险由抽检兜 |
| D-07 | 抽检归属 | C 自查 10 条，B 交叉 10 条 | B 多花 30 分钟 |
| D-08 | PM 是否写代码 | 不写 | 数据与验收外派 |
| D-09 | 拓客范围 | 导入 + 证据卡 + 英文邀约，不做抓取与打分 | 评委会追问数据来源，用“原文出处”答 |
| D-10 | 询盘范围 | 人工三分类，不做自动分类 | 少一个“智能”卖点，多一份可信 |
| D-11 | 速配范围 | 不补孔数孔距片数（P1），只承诺尺寸 | 候选卡那一行本轮可能为空 |
| D-12 | 今晚收工 | 22:00，同时交海报 | 少 2 小时编码 |
| D-13 | 演示最小集 | 三个页面都能开 + 速配出候选 + 一条跨功能跳转 | 超出这个范围的功能不算 P0 |
| D-14 | 文档颗粒度 | 五份主文档 + 四份开工单 | 只读自己那份就能开工 |
| D-15 | **v5 改功能板块制** | 由 v4 的“数据/服务/页面”改为“三块功能各一人” | 共享框架必须一次做对并冻结，A 的压力最大 |
| D-16 | 海报叙事 | 全链路闭环，视觉重量给速配 | 拓客与询盘各只占 30 秒口播 |

## 3. 三条“不要”

1. **不要**在 19:20 后新增路由或依赖。
2. **不要**为了“看起来智能”加自动分类或模型生成候选。
3. **不要**在台上说「全量 / 自动识别车桥 / 精准定价 / 100% 准确」。
