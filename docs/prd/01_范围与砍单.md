## 2. 三个功能各自做到哪

### 2.1 拓客（A）

**做**：上传或粘贴 6 行买家 CSV → 去重 → 回显新增/重复/跳过 → 每家一张证据卡（品类、采购能力、中国采购、展会意向、原文）→ 生成英文邀约（按品类选模板，展位缺失时省略展位改问行程）。

**不做**：Facebook 抓取、买家画像、采购能力打分模型、自动发送。

**演示判据**：导入 6 行得到 4 家企业 5 条证据；原样重传新增 0；点开一张卡能生成一段英文邀约。

### 2.2 询盘承接（B）

**做**：粘贴一条评论 → 出意向卡（语言、涉及车型、数量、原文）→ 人工三分类（待回复/待复核/留档，改判要填原因）→ 列表与筛选 → 卡片上的「选型」跳到速配 → 导出 CSV。

**不做**：自动分类引擎、Graph API、WhatsApp、自动回复、多语言精判。

**演示判据**：粘一条评论出卡；改分类留原因；筛选三态能切换；点选型跳到 `/fitment?q=...`。

### 2.3 车型速配（C）

**做**：153 条 CSV → `fitment.jsonl` + `alias.json` → 车型归一化与召回 → 按前/后、宽度、孔数过滤 → 候选卡（尺寸、孔数孔距片数、页码、置信度）→ 追问话术 → 勾选生成报价草稿（价格留空）→ `?mode=mobile`。

**不做**：重抽 PDF、补齐孔数孔距片数（P1）、向量库、模糊召回（P1）、型号映射、车桥铭牌。

**演示判据**：查天锦KR 出 ≥3 张卡；加前桥缩到 2 张；加宽 155 缩到 1 张；勾选能出草稿且价格为空。

## 3. 明确不做（三个功能通用）

| 不做 | 原因 |
| --- | --- |
| 新建第二个 Web 框架或换前端 | 合并会失败 |
| 加第三方依赖（pandas、requests、bootstrap） | 有人装不上，集成崩 |
| 用数据库 | 三份 schema 会打架，JSON 够用 |
| 任何 LLM 生成候选或价格 | 防幻觉红线 |
| 登录、权限、多用户 | 演示不需要 |
| 真实外网接入（Facebook、WhatsApp、孚盟） | 无权限、无时间 |
| 抽取全量产品册页 | 每页都是新的版式博弈 |
