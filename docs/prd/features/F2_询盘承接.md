# F2 · 询盘承接（本轮只做薄版：一条评论 → 一张卡 → 一个按钮）

> **范围一句话**：页面叫 `/inbox`，一个文本框粘贴评论，出一张意向卡，卡上一个「选型」按钮跳到 `/match`。
> 不做：自动分类引擎、指派、跟进、导出、邀约生成。全部归 P1。

---

## 1. 这一块解决什么问题

买家发来一条评论：「Please quote 217 sets of T850 front brake linings.」
销售要先判断：**这是什么品类、要多少、缺什么信息、该不该现在回。**

完整形态：语言识别 → 品类 → 编号 / 数量 → 采购信号 → 缺失信息 → 待回复 / 待复核 / 留档 → 指派 → 导出。

本轮只保留**链条最末端的一个动作**：从评论进到选型页。因为这是唯一能把 F1/F2 和 F3 连起来的地方，也是海报“闭环”叙事的支点。

---

## 2. 薄版范围（P0，归 D3）

### 2.1 页面要素

| 区块 | 内容 | 数据来源 |
| --- | --- | --- |
| 输入区 | 一个大文本框，预置一条示例评论；「生成卡片」按钮 | 手工粘贴 |
| 意向卡 | 语言（中/英，按字符判断）｜涉及车型（从文本里匹配 `alias.json` 的车型）｜数量（正则抓 `\d+ sets`）｜原文 | 规则，不调模型 |
| 分类 | 三个单选按钮：待回复 / 待复核 / 留档（**人工点选**，不做自动判断） | 人工 |
| 选型按钮 | 车型命中才可用 → 跳 `/match?q=<车型>&from=comment:<id>` | 点击 |
| 提示 | 车型未命中时显示「未识别车型，可手工输入」 | — |

### 2.2 硬规则

1. **不做自动分类。** 三个单选项由人点。这是本轮最重要的砍单——自动分类要模型 + 词表 + 阈值，7 小时里做不完且容易错。
2. **不写任何状态到旧系统。** 目前没有旧系统，但规则保留：`/inbox` 只读评论 + 路由跳转，不改候选、不改数据。
3. **`from=comment:<id>` 只用于页面顶部显示来源**，不参与匹配逻辑。
4. 卡片上的车型必须**来自 `alias.json` 命中**，不允许模型生成车型。

### 2.3 验收

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| V8 | 粘贴 `Please quote 217 sets of T850 front brake linings.` → 生成卡片 → 点选型 | 卡片显示英文、数量 217、车型命中（若库里没有 T850，则显示“未识别车型”+手工输入框）；点选型后进 `/match`，q 预填，页面顶部显示来源评论 |
| V13 | 在 `/inbox` 点选型 → 返回列表 | 卡片内容、分类选项不变（证明入口只读） |

## 4. 明确不做

- Facebook 评论同步 / Webhook
- WhatsApp 收件
- 多语言自动识别（只做中/英粗判）

## 5. 与 F3 的接口

```
/inbox  ──粘贴评论──▶ 意向卡  ──点击「选型」──▶  GET /match?q=<车型>&from=comment:<id>
                                                   │
                                       页面顶部显示「来源评论 #<id>」
```

- 只用一个 query 参数，**不做新状态机、不做会话表**。
- 若车型未命中，`q` 传空，`/match` 进入“未收录”态并给手工输入提示。
