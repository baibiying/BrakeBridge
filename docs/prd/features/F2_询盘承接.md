# F2 · 询盘承接（B 独占）

> 目标：**粘贴一条买家评论，30 秒内生成一张意向卡，人点一下分类，再一键跳去选型。**
> 目录：`features/inquiry/`，数据：`data/inquiry/inquiries.json`

---

## 1. 链路

```
粘贴一条评论
      ↓ 规则抽取（不调模型）
意向卡：语言 · 涉及车型 · 数量 · 原文
      ↓ 人工三分类（改判填原因）
待回复 / 待复核 / 留档
      ↓ 卡片上的「选型」
/fitment?q=<车型>&from=inquiry:<id>
```

---

## 2. 卡片字段与抽取规则

| 字段 | 规则 | 失败时 |
| --- | --- | --- |
| 语言 | 含中文字符 → 中文，否则英文 | 默认英文 |
| 涉及车型 | 在 `data/fitment/alias.json` 里找别名命中（**只读**） | 显示「未识别车型」，给手工输入框 |
| 数量 | 正则抓数字 + `sets/pcs/units/套/件` | 显示「未提及」 |
| 原文 | 原样保存 | — |

**硬规则**

1. **不做自动分类。** 三分类由人点。
2. **不允许模型生成车型。** 车型只从别名表里查。
3. `inquiries.json` 只归 B 写。速配的数据文件只读不写。

---

## 3. 数据文件

`data/inquiry/inquiries.json`：

```json
[
  {
    "id": "inq-1",
    "text": "Please quote 217 sets of T850 front brake linings.",
    "lang": "en",
    "vehicle": "",
    "qty": 217,
    "status": "待回复",
    "reason": "",
    "created": "2026-11-21T16:10:00+08:00"
  }
]
```

- `status` 只能取 `待回复 / 待复核 / 留档`。
- 从 A 改到 B 时，`reason` 必填，空的话前端拦一下。
- 每次改动即时落盘，刷新页面还在。

---

## 4. 页面

`GET /inquiry` 一页三块：

1. 输入区：一个大文本框 + 预置示例 + 「生成卡片」
2. 列表区：卡片堆叠，每张卡显示语言徽章、车型、数量、原文、三个分类按钮、当前状态
3. 筛选栏：全部 / 待回复 / 待复核 / 留档，带计数

卡片右下角按钮：`选型`（车型命中才亮）、`改判`（弹出原因输入）。

---

## 5. 跨功能跳转

```
GET /fitment?q=<车型文本>&from=inquiry:<id>
```

- 车型为空时也允许跳，速配页会进入未收录态并给手工输入框。
- `from` 只用于速配页顶部显示「来源评论 #id」。
- **B 不需要读 C 的代码，也不需要 C 的数据。**

---

## 6. 导出

`GET /inquiry/export` 返回 CSV：`id,created,lang,vehicle,qty,status,reason,text`。
文件名 `inquiries_<yyyymmdd>.csv`，UTF-8 带 BOM（Excel 打开不乱码）。

## 9. 边界

- 不做自动回复、自动发送、多轮对话。
- 不做多语言精判，中/英粗判即可。
- 不做买家画像关联（拓客的数据不读）。
