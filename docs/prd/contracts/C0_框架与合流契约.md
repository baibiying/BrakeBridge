## 3. 三个入口（URL 与 blueprint）

| 功能 | 前缀 | 主页 | blueprint 变量 | 谁的 |
| --- | --- | --- | --- | --- |
| 拓客 | `/sourcing` | `/sourcing` | `sourcing_bp` | A |
| 询盘承接 | `/inquiry` | `/inquiry` | `inquiry_bp` | B |
| 车型速配 | `/fitment` | `/fitment` | `fitment_bp` | C |

`app.py` 里一次性注册，写法固定：

```python
for module, name in [("features.sourcing", "sourcing_bp"),
                     ("features.inquiry", "inquiry_bp"),
                     ("features.fitment", "fitment_bp")]:
    try:
        mod = importlib.import_module(module)
        app.register_blueprint(getattr(mod, name))
    except Exception:
        pass          # 某个功能还没就绪时，其他页面照常可用
```

`try/except` 是必须的：B 或 C 的模块没写完时，A 的页面不能跟着崩。

首页 `/` 由 `base.html` 的导航承担，三条链接固定：

```
拓客 /sourcing ｜ 询盘 /inquiry ｜ 速配 /fitment
```

## 4. 跨功能契约（只有这三条，其余各自随意）

### 4.1 询盘 → 速配（唯一必须打通的跨功能跳转）

```
GET /fitment?q=<车型文本>&from=inquiry:<id>
```

- `q` 是 B 从评论里识别出的车型文本，命中不了就传空串。
- `from` 只用于速配页顶部显示「来源评论 #id」，**不参与匹配逻辑**。
- C 必须能处理 `q` 为空的情况：显示未收录态加手工输入框。

### 4.2 拓客 → 询盘（可选，P1）

```
GET /inquiry?q=<买家名>&from=sourcing:<id>
```

不做也不影响演示。B 若要做，同样只用于顶部显示来源。

### 4.3 页面返回约定

- 所有页面 GET 必须返回 200，不许 500（异常自己兜住，显示空态）。
- 每个功能自己的表单提交后，回到自己的页面，不跳到别人家。

## 7. 为什么这样能合得起来

- **文件不重叠**：三个人各占一个目录，Git 合并时没有共同文件可冲突。
- **共享文件只有三份，且 15:20 后冻结**：冲突窗口只有 30 分钟。
- **唯一跨功能调用是一个 URL 加一个 query 参数**：B 不需要 import C 的代码，C 不需要知道 B 的数据结构。
- **没有共享数据库**：不存在“谁先建表”的争论。

## 8. 明确禁止

| 禁止 | 原因 |
| --- | --- |
| 加新依赖（requests、pandas、bootstrap 等） | 有人装不上，集成就崩 |
| 引入前端构建工具 | 7 小时里没有编译步骤的余地 |
| 三个人共用一个模板文件 | 必冲突 |
| 把数据写进 `app.py` | 冻结文件改不了 |
| 用 SQLite 建表 | 三份 schema 会打架，JSON 够用 |
| 改端口 | 演示脚本按 5000 写 |
