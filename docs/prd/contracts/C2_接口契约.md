# C2 · 跨功能契约与页面约定（冻结）

> 三个功能之间**只有两个 URL**。除此之外不共享代码、不共享数据、不共享模板。

---

## 1. 路由总表

| 方法 | 路径 | 谁的 | 说明 |
| --- | --- | --- | --- |
| GET | `/` | A（框架） | 首页，三条导航链接 |
| GET/POST | `/sourcing` | A | 导入名单 + 证据卡 |
| POST | `/sourcing/invite` | A | 生成英文邀约 |
| GET/POST | `/inquiry` | B | 粘贴评论 + 卡片列表 |
| POST | `/inquiry/classify` | B | 改分类（带原因） |
| GET | `/inquiry/export` | B | 导出 CSV |
| GET | `/fitment` | C | 选型页 |
| POST | `/fitment/match` | C | 匹配（返回 JSON 或直接渲染） |
| POST | `/fitment/quote` | C | 生成报价草稿 |

**路由不许重名。** 前缀写死：`/sourcing`、`/inquiry`、`/fitment`。

---

## 2. 跨功能跳转（唯一的两个）

### 2.1 询盘 → 速配（必须打通）

```
GET /fitment?q=<车型文本>&from=inquiry:<id>
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `q` | string | ✅（可为空串） | 车型文本，命中不了就给空串 |
| `from` | string | ❌ | 只用于页面显示「来源评论 #id」 |

**C 必须处理的情况**

- `q` 为空 → 显示未收录态 + 手工输入框，不报错。
- `q` 有值但未命中 → 未收录态 + 最相近 3 个。
- `from` 存在 → 页面顶部显示一行来源，**不参与匹配**。

### 2.2 拓客 → 询盘（可选，P1）

```
GET /inquiry?q=<买家名>&from=sourcing:<id>
```

不做也不影响演示。B 若做，只用于顶部显示来源。

## 3. 页面约定

| 约定 | 内容 |
| --- | --- |
| 状态码 | 所有 GET 页面返回 200。异常自己兜住，显示空态，不许 500 |
| 空态 | 无数据时显示一句说明 + 一个可操作按钮，不许白屏 |
| 导航 | 统一用 `templates/base.html`，三条链接固定 |
| 样式 | 只用 `static/base.css`，功能内联样式写在各自的页面里 |
| 中文 | 页面文案中文，示例评论与邀约用英文 |
| 端口 | 5000，不许改 |

---

## 4. 各功能内部接口自由

以下这些**不需要跨人约定**，各自看着办：

- A 的 CSV 解析函数、去重逻辑、邀约模板拼装
- B 的语言判断正则、数量抽取正则、卡片渲染
- C 的归一化、召回、置信度算法、报价草稿组装

**唯一例外**：B 读 `data/fitment/alias.json` 找车型，字段结构见 C1 §3，**只读**。

---

## 5. 错误处理约定

1. 表单提交失败时，回到自己页面并显示一句人话，不抛栈。
2. 任何 `except` 必须至少打印一行 stderr，不许静默吞。
3. 页面 500 视为阻断 bug，联调时优先修。
