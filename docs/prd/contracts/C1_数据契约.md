## 2. `fitment.jsonl` 字段表

一行一条，UTF-8，字段名与下面完全一致（D2 的代码按字段名取值，不按位置）。

| 字段 | 类型 | 必填 | 取值 / 说明 |
| --- | --- | --- | --- |
| `id` | string | ✅ | `<品牌缩写>-p<页码>-c<列>-r<行>`，例 `KL-p27-c1-r6`；**全库唯一** |
| `brand` | string | ✅ | `KOOYING` / `GUANLONG` |
| `src` | string | ✅ | 原始文件名，例 `kooying catalog.pdf` |
| `page` | int | ✅ | PDF 页码（从 1 开始，不是 PDF 内部标签） |
| `cell` | string | ✅ | `c<列>r<行>`，与 `id` 后半段一致 |
| `vehicle_raw` | string | ✅ | 原文车型名，保留 `(ABS)`、`前A`、括号全半角 |
| `vehicle_norm` | string | ⚠️ | 归一化后的基础车型名；`status=name_only` 时可为空 |
| `position` | string | ⚠️ | `前` / `后` / `null`（原文没写就 null，不猜） |
| `variant` | string | ⚠️ | `A` / `B` / `null` |
| `size_raw` | string | ⚠️ | 原始尺寸串，例 `188×155×12.2/14`；无尺寸时 null |
| `l` `w` | number | ⚠️ | 长、宽（mm） |
| `t1` `t2` | number | ⚠️ | 厚度；`t2` 无则为 null（例 `201×160×15.5` 只有 t1） |
| `holes` | int/null | ⚠️ | 孔数，**语义待企业确认** |
| `pitch` | int/null | ⚠️ | 孔距，**语义待企业确认** |
| `pieces` | int/null | ⚠️ | 片数，**语义待企业确认** |
| `raw_nums` | string | ⚠️ | 表里三个数字的原串，例 `"10 120 8"`；语义确认后回填上面三列 |
| `oe` | array | ✅ | OE 号数组，无则 `[]` |
| `status` | string | ✅ | `ok` / `待核` / `name_only`（见 §3） |
| `confidence` | number | ✅ | 0~1；抽取置信度，不是匹配置信度 |

### 2.1 关于 `holes` / `pitch` / `pieces` 的硬规定

- 企业**没有确认**这三个数字的语义。开发照常使用，但：
  1. 必填 `raw_nums` 原串；
  2. UI 上显示为「孔数 / 孔距 / 片数」，并在候选卡“待核项”里写明「第 3、4 个数字语义待企业确认」；
  3. **台上不许说“孔距 120”这类断言**，只能说“表里这三个数字，我们按孔数/孔距/片数理解”。

## 3. `status` 取值规则

| 值 | 含义 | 判定 |
| --- | --- | --- |
| `ok` | 车型 + 尺寸都有，且两册交叉校验不冲突（或只有一册有） | 默认值 |
| `待核` | 两册同名车型尺寸无交集 / 抽取疑似错位 / 数字缺位 | 必须写进质量报告 |
| `name_only` | 只有车型名、没有尺寸 | 不参与候选展示，只参与“最相近车型”提示 |

**展示规则**：`ok` 正常展示；`待核` 展示但角标标「待核」；`name_only` 不进候选列表。

## 4. `alias.json` 格式

```json
{
  "东风天锦KR": ["天锦", "天锦KR", "东风天锦", "EQ天锦", "天锦KR前"],
  "红岩杰狮":   ["杰狮", "杰狮C6", "上汽红岩", "GENLYON"],
  "解放虎威":   ["虎威", "小虎威", "解放虎V", "J6虎威"]
}
```

- 键 = `vehicle_norm`（基础车型名），值 = 别名数组。
- 被归一化吃掉的尾部标记（`前` `后` `A` `B` `(ABS)` `（ABS）`）**不需要**写进别名。
- 规模：**30~50 条**，必须覆盖演示用 3 个车型（天锦KR / 杰狮C6 / 汉德桥35T）。
- 同一别名不许出现在两个键下（D2 启动时做一次冲突检查，冲突则打印警告并取第一个）。
