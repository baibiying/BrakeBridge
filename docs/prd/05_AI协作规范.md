# 05 · 与 AI 协作的动作标准

> 目的：让 AI 变成“按时交 ticket 的结对开发”，而不是“聊得很好但交不出东西”。
> 四个人共用 §0–§3，各自再按 §4 的专属条款执行。

---

## 0. 三条总则

1. **一次只给 AI 一个 ticket。** 做完立刻跑验证、立刻 commit，不攒到最后一起提交。
2. **AI 说的话不算数，命令输出才算数。** 每个 ticket 结束必须要求它贴出实际运行的命令与输出。
3. **AI 不许碰别人的目录和冻结文件。** 提交前 `git status` 看一眼，越界的 diff 直接 `git checkout --` 回滚。

---

## 1. 每次对话的固定开头（复制改三处）

```
角色：你是我的结对开发，只做我指定的这一个 ticket，不做其他改进。
上下文：读 docs/prd/contracts/C0_框架与合流契约.md，再读 docs/prd/kickoff/开工_<我>.md。
        只允许改 features/<我的>/ 与 data/<我的>/。
任务：<ticket 编号> <一句话描述>
约束：不改 app.py、templates/base.html、static/base.css、requirements.txt；
      不加任何依赖；不重构既有代码；不写测试以外的额外文件。
交付格式：1 改了哪些文件 2 我该跑的验证命令 3 你实际跑的输出 4 没覆盖的验收项。
```

**为什么要给“交付格式”**：不给的话，AI 会交一大段解释，你拿不到能跑的东西。

---

## 2. 每次结束的固定四问（少一问就等于没验收）

| # | 问什么 | 不合格的回答 |
| --- | --- | --- |
| 1 | 「贴出你实际跑的命令和输出」 | 只说“应该可以” / 没跑就贴输出 |
| 2 | 「列出现在改了哪些文件」 | 列出一堆没让你改的文件 |
| 3 | 「我这几个验收里，哪条你没覆盖」 | 说“全部覆盖”但没对照编号 |
| 4 | 「如果我现在重启服务，哪些会丢」 | 答不上来，说明持久化没做 |

---

## 3. 对 AI 的禁止清单（出现任何一条，这个提交不要）

| 禁止 | 具体表现 | 处理 |
| --- | --- | --- |
| 顺手优化 | 改了没让你改的函数、格式、注释 | revert |
| 编造数据 | 凭空写页码、型号、尺寸、公司名 | revert |
| 合并 ticket | 一次提交里做了三个任务 | 拆开重做 |
| 假称完成 | 没跑通就说“已实现” | 要求先跑 |
| 改契约 | 动了 `contracts/` 或 `app.py` | revert，找 PM |
| 加依赖 | 引入 requests / pandas / bootstrap | revert |
| 无限调试 | 同一问题改了 3 次还不过 | 停，按降级方案走 |

**单次时间盒**：一次对话不超过 20 分钟。超过就停，把现状 commit，换下一个 ticket。

---

## 4. 每人专属标准

### 4.1 A · 拓客

| 动作 | 标准 |
| --- | --- |
| 起手 | 先让 AI 输出**目录树 + `app.py` 全文 + `base.html`**，确认后才写第二个文件 |
| 时限 | 框架只给 AI **30 分钟**，超时就自己手写最小可跑版 |
| 每次改完 | 必须跑 `python app.py`，然后访问 `/`、`/sourcing`、`/inquiry`、`/fitment` 四个路径 |
| 15:30 之后 | **不许再让 AI 碰** `app.py`、`base.html`、`base.css`，只让它改 `features/sourcing/` |
| 解析代码 | 让 AI 先给“6 行输入 → 期望输出”的对照表，再写代码；代码跑完后逐行核这张表 |
| 禁止 | 不许让 AI 引入 Flask-WTF、Tabler、openpyxl；不许它“顺便”做上传 |
| 交付 | 每个 ticket 用一条 commit，message `a: <ticket> <一句话>` |

### 4.2 B · 询盘

| 动作 | 标准 |
| --- | --- |
| 起手 | 先让 AI 写 **3 条输入评论 → 期望卡片字段** 的表格，确认后再写抽取代码 |
| 正则 | 必须要求 AI 同时给 **2 条不该命中的反例**，你和它一起跑 |
| 分类 | 分类永远由人点，**AI 只做字段抽取**，不许让它加自动分类 |
| 跳转 | 让 AI 只输出一个 `url_for(...)` 或一个 `<a href>`，不许它改前端结构 |
| 抽检（20:30 后） | AI 只能做**逐条对照表**，判定由你看 PDF 做；不许让 AI 说“这条应该对” |
| 禁止 | 不许 AI 读 `data/fitment/` 以外的别人数据；不许它写 `fitment` 的任何文件 |
| 交付 | `b: <ticket> <一句话>` |

### 4.3 C · 速配

| 动作 | 标准 |
| --- | --- |
| 数据 | 先让 AI 输出**字段映射表 + 前 5 行 jsonl 样例**，你确认字段名后再批量 |
| 字段 | 只给 C1 里的字段名，**不许让 AI 起新名字** |
| 匹配 | 让 AI 先写**测试用例表（V1–V7 的输入与期望）**，再写算法；跑完逐条对 |
| 页面 | 卡片四行顺序写死在 C0/F3，AI 不许改顺序或加字段 |
| 抽检 | AI 只做“pdf 原文 vs jsonl”的对照表，判定由你看 |
| 禁止 | 不许 AI 生成任何型号、尺寸、页码；不许它补 `holes/pitch/pieces` 的猜测值 |
| 每次改完 | 跑三条查询：天锦KR / 杰狮C6 / 汉德桥35T，贴输出 |
| 交付 | `c: <ticket> <一句话>` |

### 4.4 PM · 海报与展演

| 动作 | 标准 |
| --- | --- |
| 只做文案 | 让 AI 输出**可直接粘贴的成稿**，不要备选、不要“你可以考虑” |
| 数字核对 | AI 给的每个数字，你必须回到 `C1` 或 `F3` 核一遍；对不上就删 |
| 海报 | 让 AI 给**逐块文字 + 排版指令**，不给设计稿；设计你自己在 Canva 里做 |
| 路演 | 让 AI 把口播稿压到秒数内，超时它会自动砍，你只需确认 |
| 禁止 | 不把企业真名、联系人、电话贴给 AI；不让 AI 写代码或改仓库文件 |
| 交付 | 文案存 `docs/prd/demo/`，不新开目录 |

## 5. 每个 ticket 结束的四个动作（固定顺序）

```bash
git status                      # 1 只改了自己的目录？
<跑验证命令>                    # 2 输出贴群里
git add <自己的目录> && git commit -m "<人>: <ticket> <一句话>"   # 3
# 4 群里报一行：ticket 编号 + 通过/降级
```

---

## 6. 出问题时的三步

| 现象 | 动作 |
| --- | --- |
| AI 改了三轮还不过 | 停，按 kickoff 的「卡住怎么办」降级，先把能跑的 commit 掉 |
| AI 的输出与契约不符 | 以契约为准，把契约原文贴给它，让它改 |
| 发现 AI 编了数据 | 立刻 revert 那次提交，在群里说一句，不要私自修 |

---

## 7. 一句话记忆

**给 AI 一个 ticket、一份契约、一个交付格式；要它贴命令输出；只合自己目录；20 分钟不过就降级。**
